# 6. Models and residuals

## 6.1 A model is a statement about what is boring

`goad_toolkit.models` is four functions and about forty lines. That is deliberate: the point
is not to provide modelling capability — sklearn and statsmodels exist — but to make the
*act of stating a model* small enough that there is no excuse for skipping it.

```python
from goad_toolkit.models import linear_model, mse, train_model

params = train_model(X, y, model_fn=linear_model, loss_fn=mse,
                     params=[0.01, 1.0], bounds=[(0, 1.0), (0, None)])
yhat = linear_model(X, params)
residual = y - yhat
```

Three pieces, each replaceable:

- **`model_fn(x, params) -> yhat`** — your hypothesis about the shape of the relationship.
- **`loss_fn(y, yhat) -> float`** — what counts as wrong.
- **`train_model`** — `scipy.optimize.minimize` over the parameters, with optional bounds.

Writing your own model function is the normal case:

```python
def exponential_model(x, params):
    a, b, c = params
    return a * np.exp(b * x) + c
```

It has to accept `(x, params)` and return an array the same length. Nothing else.

**Bounds are how you inject knowledge.** `bounds=[(0, 1.0), (0, None)]` says the slope is a
positive fraction and the intercept is non-negative — because deaths cannot be negative and
one case cannot cause more than one death. This is domain knowledge, expressed in two tuples,
and it is often the difference between a fit that converges somewhere sensible and one that
does not converge at all.

## 6.2 The four shapes worth knowing

Most univariate relationships you will meet are one of four basis functions, or a composition
of them. Recognising which one you are looking at is more useful than any amount of
automated model selection.

| Shape | Function | Generated by | Looks like |
|---|---|---|---|
| linear | `a·x + b` | a constant rate of change | a straight line |
| sinusoidal | `a·sin(ωx + φ) + b` | a cycle | a repeating wave |
| exponential | `a·e^(bx) + c` | growth proportional to current size | a curve that gets steeper |
| logistic | `L / (1 + e^(-k(x - x₀)))` | exponential growth into a limit | an S-curve |

`linear_model` and `logistic` ship. The other two are three lines each.

The logistic is worth dwelling on because it is what almost every real "exponential growth"
turns out to be — epidemics, adoption curves, population, any process consuming a finite
resource. Everything grows exponentially until it stops, and the whole question in practice
is where the inflection point `x₀` is. Fitting a logistic to data that has not yet passed its
inflection is close to unidentifiable, which is a useful thing to know before you claim a
ceiling.

Composition covers most of the rest: a trend plus a cycle is `linear + sinusoidal`, and that
is exactly what `seasonal_decompose` is doing when it splits a series into trend, seasonal
and residual components.

## 6.3 The residual workflow

```python
data["predicted"] = linear_model(X, params)
data["residual"] = y - data["predicted"]
```

Then look at it, in this order — each step answers a different question.

**1. Residual against time.** Is there a period where the model is consistently wrong? A
step, a drift, a widening spread? `ResidualPlot` draws exactly this, with `VerticalDate` for
marking the moment you think something changed.

```python
from goad_toolkit.visualizer import ResidualPlot, PlotSettings

settings = PlotSettings(figsize=(12, 6), title="Residual", xlabel="date", ylabel="error")
fig, ax = ResidualPlot(settings).plot(
    data=data, x="date", y="residual",
    date="2021-01-06", datelabel="Vaccination started",
)
```

**2. Residual against the predictor.** Is the model wrong specifically for large x, or small
x? That is a shape problem — you fitted a line to a curve.

**3. Residual against the prediction.** A fan shape (spread growing with the predicted value)
means the error is proportional rather than additive, which usually means you should have
modelled the log.

**4. The distribution of the residual.** Symmetric and light-tailed means you are done.
Anything else is a lead. See [Distributions](05-distributions.md) §5.8.

**5. Autocorrelation of the residual.** If today's error predicts tomorrow's, there is
temporal structure the model has not captured, and any uncertainty estimate you compute is
too small.

## 6.4 The covid example, end to end

`demo/linear.py` is the whole loop in one script. Read it alongside this section.

1. **Question.** Do deaths track positive tests with a delay, and does that relationship stay
   stable?
2. **Enrich.** `CovidDataProcessor` differences the cumulative deaths, shifts them by fourteen
   days, restricts to a date range, smooths both series with a 7-day rolling average, and
   z-scores them.
3. **Look.** `ComparePlot` puts the two z-scored series on one axis. They track. So far this
   is a plot everyone expected.
4. **Model.** A linear model, deaths from positive tests, with bounds encoding that the slope
   is a positive fraction.
5. **Residual.** `ResidualPlot` over time, with a vertical line at the start of vaccination.
   The residual is not flat around that date — the model built on the earlier relationship
   systematically over-predicts afterwards.
6. **Fit.** `DistributionFitter` on the residual, `PlotFits` to see the candidates ranked.

The finding is step 5, and it is only visible because of step 4. In the raw series, the
change is buried under the part the model explains. This is the argument for modelling in a
visualisation course: the model is a subtraction that reveals.

## 6.5 Overfitting, in the smallest useful form

Add parameters and the loss goes down. It always does. `np.polyfit(x, y, 15)` will pass very
close to every point you have and be useless one step beyond them.

Three defences, in order of how often you should reach for them:

1. **Look at the fitted curve.** Between your data points, is it doing something a mechanism
   could produce? A model that oscillates wildly between observations is fitting noise, and
   you can see it.
2. **Hold data out.** Fit on part, measure on the rest. If the loss is much worse out of
   sample, the extra parameters bought you nothing real.
3. **Regularise.** Penalise large coefficients, so a parameter has to earn its place. L2
   shrinks everything smoothly; L1 drives coefficients to exactly zero and so doubles as
   feature selection; elasticnet mixes them.

And the framing that outlasts the techniques: **the map is not the territory**. A model is a
useful compression of the data, and every compression discards something. The question is
never "is the model true" — it is not — but "is what it discarded relevant to the decision I
am about to make". A linear model of a curved relationship is fine for interpolating in the
middle and disastrous for extrapolating at the edge, and it is the same model in both cases.

## 6.6 Model, or distribution?

Both are models. They answer different questions and it is worth being explicit about which
you are doing.

- **A functional model** (`y = f(x)`) says how one variable depends on another. Use it when
  you have a predictor and a response and you care about the relationship.
- **A distributional model** (`y ~ D(θ)`) says how a variable is spread with no predictor at
  all. Use it when the question is about typical values, spread, or how unusual something is.

They compose: the residual of a functional model is what you fit a distribution to. That
composition is the loop from [Goal oriented analysis](01-goal-oriented-analysis.md) §1.3, and
it is where the two halves of this library meet.
